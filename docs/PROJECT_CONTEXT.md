# Standing Orders project context

Standing Orders is a local task system for a lead agent and subordinate crews. Browser Chat and CLI chat share conversation identity and task operations. SQLite is authoritative for tasks, decisions, saved context, results and delivery status. Repository indexes are disposable aids.

The normal task flow is plan → approved work → Ready → explicit Complete or revision. There is no separate model-review stage and no automatic evidence repair/resubmission. Missing optional historical assessments do not block completion. Real failed checks and damaged saved material remain visible. Completion never changes a check result or proves deployment.

Use Chat, Tasks and Projects as the everyday UI. One state, concise outcome and one clear primary action belong at the top. Put secondary diagnostics and history in disclosures. Preserve scope, irreversible consequences and approval terms before consent. Verify actual desktop and phone behavior.

The lead gets a bounded DB catch-up, curated project knowledge, and relevant source excerpts. A task retains its selected context. Static import impact is advisory; stale or missing indexing falls back to search. Explicit user decisions can become proposed knowledge updates; agent assertions are not approved instructions.

Automatic crew updates are opt-in. Deterministic idle scans use no model; meaningful updates use the same authorized conversation and budget. Persisted request identities allow acknowledgment recovery without generating a second response. Failed responses do not rerun crew work.

Use the latest verified installed tool for live work. A source merge or package build is not deployment: UI, worker and resolved CLI must agree. Follow normal drain, backup, database compatibility, process-exit and health checks. No Mac restart is required for an ordinary update. Never replace a runtime underneath active work.

Use focused checks while implementing and the unchanged approved full verifier once at the final native candidate gate. Deployment requires the exact passing native check and that exact result marked Complete. Preserve authorization, transaction, migration, cancellation, durable-delivery and rollback coverage; remove only dead behavior and redundant coverage with a concrete reason.
