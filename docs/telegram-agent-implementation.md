# Telegram project agent implementation log

Started 2026-09-06. This is the working record for the four-step plan approved in the product conversation. Entries distinguish implemented behavior, validation, and remaining work.

## Intended outcome

One project manager conversation across Telegram, desktop, and web: reliable answers, evidence-backed investigation, explicit confirmations for changes, and continuity across projects and days. Existing task scope and publication approvals remain authoritative. A question must never silently authorize work.

## Steps and acceptance criteria

1. **Reliable responses** — acknowledge accepted questions, show ongoing progress, deliver a final answer or explicit failure, and recover queued replies after interruptions without duplicating actions or model spending.
2. **Real investigation** — inspect authorized task history, run evidence, changes, and publication records; include evidence references; distinguish local commits from publication and uncertainty from facts.
3. **Actions in the conversation** — propose creating, prioritizing, holding, and resuming tasks; present clear Telegram confirmation buttons; use the same validated actions and history as the app. Replays and stale cards must not repeat mutations.
4. **Persistent context and richer input** — retain conversations and explicit project context across days, distinguish project workstreams, support screenshots/documents/voice where the connected provider can process them, and provide useful unsupported-input errors.

## Starting state

- The working tree contains the ongoing desktop/UI/chat work and an earlier Telegram polling fix. These changes are preserved.
- The Telegram question queue and app share the local Claude Code conversation engine. Questions receive a bounded metadata snapshot and can produce task drafts only.
- Existing decision buttons work. General task proposals require returning to app Chat.
- Conversation content currently expires after 24 hours. Telegram rejects attachments.
- Repository conventions: Node standard library, no new runtime dependencies, real SQLite/repository regression tests, authoritative approval and project access checks.

- This is one shared conversation with persistent project focus and searchable history, not independent simultaneous model conversations for each project.
- Telegram delivery is at least once: a crash after Telegram accepts a send but before its receipt is saved may repeat that message. Confirmed mutations remain idempotent.
